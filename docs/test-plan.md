# 测试计划

> **这份文档是什么**：测什么、怎么测、自动测试和手动走查各管什么。
> **什么时候用**：提交 PR 之前；新增视图或动画时，同时补测试。

## 1. 测试分层

| 层 | 管什么 | 怎么做 | 什么时候 |
|---|---|---|---|
| 冒烟测试（自动） | 页面能打开；每台设备、每个视图、每个演示的每一步在所有风格、中英文、两种宽度下都不报错；没有横向滚动；英文模式下没有漏翻的中文 | `node tests/smoke.js` | 每次提交 PR 前 |
| 验收走查（手动） | spec 里的验收标准逐条检查；画面是否清楚、文字是否被遮挡 | 按 spec 打开对应视图，截图 | 每个功能完成时 |
| 内容核对（手动） | 讲解、字段、参数是否与来源一致；是否标了示意 | 对照 `SRC` 里的链接 | 每课完成时 |
| 学习验收（产品负责人） | 学完能否达到产品规划书的「学会的标准」 | 产品负责人自己学一遍 | 每个里程碑结束 |

## 2. 冒烟测试

```bash
node tests/smoke.js            # 全量：4 台设备 × 8 风格 × 中英文 × 1400/390 宽度
node tests/smoke.js --quick    # 快速：只跑默认风格
```

依赖：Playwright（开发环境已预装，`require('playwright')` 可用）。页面本身不依赖它。

输出：每个组合一行，最后一行 `PASS` 或 `FAIL`。失败时退出码非 0。

检查项：

1. `pageerror` 和控制台 `error` 为 0。
2. 页面宽度不超过视口（无横向滚动）。
3. 英文模式下，舞台和讲解面板中没有未翻译的中文（允许的位置：命令行输出、品牌、术语对照副标题、页面声明）。

## 3. 截图检查

需要人眼确认的画面（新动画、新布局），用 Playwright 截图：

- 自己检查用 `deviceScaleFactor: 1`；给产品负责人看的用 `deviceScaleFactor: 2`。
- 至少覆盖：默认风格（手账笔记）、一个暗色风格（霓虹机房或黑板粉笔）、手机宽度 390。

## 4. 发布前检查

1. `node tests/smoke.js` 通过。
2. 打包 Artifact 单文件（CSS、JS 内联，去掉 doctype/html/head/body 外壳），用同样的脚本对单文件再跑一次快速测试。
3. 发布到同一个 Artifact 地址。

## 5. 以后补充

- M1 之后：针对播放器的测试（任意跳步后的状态和顺序播放到该步一致）。
- 课程数据校验：每个报文操作引用的层和字段都存在于协议字典；每个讲解条目都有英文版和来源。
