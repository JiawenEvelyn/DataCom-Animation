# 0002 · 报文用分层数据建模

- 状态：提议（在 spec 001 评审时一起确认）
- 日期：2026-11-06

## 背景

现在的报文动画是「一个彩色圆点 + 一段文字」。学习者看不到报文的结构、每层带什么关键信息、经过设备时哪些字段变了。产品规划书把「报文是主角」列为产品原则，后面的 MPLS、SRv6、EVPN 课程更需要看清多层封装。

## 可选方案

### 方案 A：每一步写一张静态的报文图

- 优点：简单，想画什么画什么。
- 缺点：每一步都要手写完整报文，重复多、容易前后不一致；没法自动标出改动。

### 方案 B：报文是分层数据，步骤里写「操作」

报文是层的数组，每层有字段。步骤里写 `set`（改字段）、`push`（封装一层）、`pop`（解封装一层）。引擎从初始报文依次执行操作，得到每一步的报文，并自动标出改动的字段和增减的层。

- 优点：数据少、不会前后矛盾；改动自动高亮；同一份数据既能画透视面板，也能画舞台上的报文色条；层的定义可以在所有课程间共用。
- 缺点：引擎要多写一些代码；需要先定义协议字典。

### 方案 C：按真实字节建模

- 优点：最真实，可以做字节视图。
- 缺点：每课都要写出完整字节，成本高；学习者大多数时候只需要关键字段。

## 决定

选方案 B。字节视图作为以后的 P2 功能，可以在方案 B 的基础上按层补字段长度来实现。

## 后果

- 需要一个协议字典 `LAYERS`：每层的名称（中英文）、颜色变量、字段列表、字段说明和来源（字段定义以 RFC 和华为公开文档为准）。
- 课程数据只写关键字段，透视面板只显示这些字段；不展示的字段不代表不存在，面板上要说明「只列关键字段」。
- 示例地址、端口等数值标「示意」。
