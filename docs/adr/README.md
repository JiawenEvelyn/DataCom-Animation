# 架构决策记录（ADR）

> **这份文档是什么**：ADR（Architecture Decision Record）记录每一个重要的技术选择：当时的背景、考虑过哪些方案、最后选了什么、带来什么后果。
> **什么时候用**：要做影响全局、以后不容易改的技术选择时，写一份新的 ADR；想知道「为什么当初这么做」时来这里查。

## 为什么要写 ADR

代码只告诉你「现在是什么样」，不告诉你「为什么是这样」。半年后想改某个设计，如果不知道当初的理由，要么不敢改，要么改了又踩回当初避开的坑。ADR 就是把理由留下来。

## 规则

- 一个决定一份文件，编号递增：`NNNN-短标题.md`，按 [template.md](template.md) 写。
- 写完后状态是「提议」，产品负责人确认后改为「已接受」。
- 已接受的 ADR 不再修改内容。决定变了就写一份新的，旧的状态改为「被 NNNN 取代」。
