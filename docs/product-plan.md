## 一、产品愿景与目标

**一句话愿景**：做一个能把数据通信网络「看透」的学习网站。学习者能看见设备内部怎么工作、报文在网络里长什么样、每一跳怎么变，从而真正理解网络的底层原理。

**要解决的问题**：数通知识很抽象。报文结构、表项、协议交互都看不见，官方文档面向的是配置和运维，不是从零理解原理。现在的演示「想一点改一点」，缺少整体知识框架和统一的展示方式。

**目标用户**

| 用户 | 背景 | 想要什么 |
| --- | --- | --- |
| 主要用户：数通领域的软件工程师 | 懂编程、懂软件，不熟悉设备和协议细节 | 理解自己写的软件对接的网络到底在做什么：报文、表项、协议状态 |
| 次要用户：网络方向新人 | 学过计算机网络课 | 把课本知识和真实设备、真实业务对应起来 |

**「学会」的标准**：学完一个主题后，学习者应该能做到下面几件事。

1. **说清结构**：画出相关报文的分层结构，说出关键字段的含义。比如 L3VPN 报文为什么有两层标签。
2. **推演过程**：给一个拓扑和一个报文，一步步推出它经过哪些设备、查哪些表、哪些字段被改写。
3. **读懂设备**：看懂对应的配置命令和 display 输出，知道每一行对应原理中的哪一步。
4. **预判故障**：能回答「如果某处配错或断开，会发生什么」。

**产品原则**

- **报文是主角**：每个演示都以「数据长什么样、在哪里被改变」为核心，不只是一个点在线上跑。
- **学习者掌控节奏**：默认手动「下一步」，每一步停下来看清文字、报文和表项。
- **结构化、可追溯**：每个知识点挂在知识地图上，内容有公开出处，示意和通用原理明确标注。
- **够用就好**：设备和协议做到理解原理所需的深度，不做设备仿真器。

## 二、知识体系

**学习范围：运营商 IP 网络**（骨干网、城域网、IP 承载网），不包括园区网和企业网。知识体系按这个范围分成 12 个领域。划分参考了华为公开的 [HCIA-Datacom 考试大纲](https://huawei.ifrn.edu.br/pdfs/hcia-datacom-v1.0-exam-outline.pdf)（打基础的部分）和 [华为 ICT 大赛网络赛道大纲](https://cloud.uobasrah.edu.iq/uploads/2022/09/15/4631Huawei%20ICT%20Competition%202022-2023%20Exam%20Outline%20-%20Network%20Track.pdf)（覆盖 OSPF、IS-IS、BGP、MPLS VPN、SR-MPLS、SRv6、BGP EVPN、QoS、组播、NETCONF/YANG、Telemetry 等），再去掉其中园区和企业网专属的内容。最初点名的业务（IGP、BGP、L3VPN、SRv6 Policy、EVPN、QoS、PCEP、隧道）全部列为 P0。

优先级说明：**P0** = 核心，必做；**P1** = 重要，第二批做；**P2** = 拓展，有时间再做。「关键报文 / 数据结构」就是报文透视要画出来的东西。

| 领域 | 知识点 | 优先级 | 关键报文 / 数据结构 |
| --- | --- | --- | --- |

## 三、学习路径

主线一共 8 步，每一步都以前一步为前置：L3VPN 要先懂 BGP 和 MPLS，SRv6 Policy 要先懂 IGP 和 IPv6，EVPN 要先懂 BGP 和隧道。两侧的 QoS、安全、可靠性、管理自动化是专题，前置学完就能插进来。

**学习路径（主线 8 步，从上往下学）**

1. 网络基础：分层封装、以太网、IP、ARP、TCP/UDP、IPv6
2. 运营商网络与设备（设备部分已完成）：骨干/城域分层、PE/P 角色、RIB/FIB
3. 链路与基础组网：接口与子接口、链路聚合、静态路由、逐跳转发
4. IGP：IS-IS / OSPF，邻居、LSDB、SPF 算路
5. BGP：iBGP/eBGP、路径属性、RR、MP-BGP
6. MPLS、L3VPN 与隧道：标签转发、LDP、VRF/RD/RT、GRE
7. SRv6 与 SRv6 Policy、PCEP：SID、SRH、控制器算路
8. BGP EVPN：EVPN 路由类型、EVPN L3VPN / E-LAN

**旁支专题（学完前置即可插入）**：管理与自动化（NETCONF、Telemetry，第 2 步后）、QoS（分类、队列、限速，第 3 步后）、网络安全（控制面保护、ACL、DDoS 清洗，第 3 步后）、可靠性（BFD、TI-LFA、VPN FRR，第 4 步后）。

每个模块开头会列出前置知识，没学过的可以一键跳回去补。

## 四、产品层次结构

内容按「站点 → 模块 → 课 → 场景 → 步骤」五层组织，每一层都是数据（不是写死在代码里的画面），这样新增一课只需要写内容。现在的「设备结构」就是模块 2，已有的原理演示会迁移成它下面的课和场景。

**产品层次结构（5 层内容 + 6 个工具）**

| 层 | 是什么 | 例子 |
|---|---|---|
| 站点 Site | 知识地图、学习进度、语言与风格切换 | 数通实验室首页 |
| 模块 Module | 知识体系里的一个主线步骤或专题，开头列前置知识 | 6. MPLS、L3VPN 与隧道 |
| 课 Lesson | 15～30 分钟学完的一个主题：目标、讲解、演示、测验 | L3VPN 的报文怎么走 |
| 场景 Scenario | 一张拓扑或设备视图 + 若干条演示流程 | CE1–PE1–P–PE2–CE2 拓扑 |
| 步骤 Step | 一句讲解 + 报文此刻的样子 + 表项变化 + 高亮部件 | PE1 压入两层标签，外层走公网，内层认 VPN |

每一层包含多个下一层，最小单位是「步骤」。贯穿各层的工具：报文透视、表项面板、模拟命令行、设备图鉴、术语表、小测验。

每课的固定结构：学习目标（3 条以内）→ 前置知识 → 场景演示 → 配置与 display 对照 → 小测验 → 参考资料。

## 五、功能设计

核心是两件事：一是「分步播放器」，让学习者自己控制节奏；二是「报文透视」，让每一步都能看到报文的完整结构和变化。这两个分别解决你提的问题二和问题一，是后面所有业务演示的地基。

### 5.1 页面布局

- **桌面**：左边是舞台（拓扑或设备图），舞台下方是步骤栏，不再盖在图上；右边是工具栏，分「讲解 / 报文 / 表项 / 命令行」四个标签页。播放演示时自动切到「报文」。
- **手机**：舞台、步骤栏、工具栏从上往下排，步骤栏固定在舞台下方。

### 5.2 分步播放器（解决问题二）

- **默认手动**：每步动画播完就停在这一步的结束状态，等学习者点「下一步」。支持键盘 ← →。
- **可选自动播放**：一个开关加三档速度。每步停留时间按文字长度算，保证来得及读完。
- **步骤列表**：列出所有步骤的标题，可以点击跳到任意一步；另有「重播本步」。
- **状态可回退**：每一步的报文、表项、高亮都由数据描述，后退时完整还原，不会留下上一步的痕迹。

### 5.3 报文透视（解决问题一）

- **报文是数据**：每个报文用分层结构描述，比如「以太网头 → MPLS 标签 → IP 头 → TCP 头 → 数据」，每层列出字段和取值。每一步都给出报文此刻的完整样子。
- **舞台上的报文块**：报文不再是一个点，而是一条分层色块（Eth | IP | TCP | Data）。压标签、加 SRH、加 VXLAN 外层时，色块会变长，一眼就能看出封装变化。
- **透视面板**：按层展开字段表。本步改变的字段高亮，并显示「旧值 → 新值」；点字段看一句解释。新加一层从左侧滑入，剥掉一层则滑出。
- **字节视图（P2）**：按真实长度比例画各层，用来理解封装开销和 MTU。
- **协议字段字典**：每种协议的字段（名称、长度、含义、出处）集中维护一份，所有课共用。第一批：Ethernet/802.1Q、IPv4、IPv6、TCP/UDP、ARP、ICMP、MPLS、GRE、ESP、SRH、VXLAN。
- **协议消息**：OSPF、BGP、PCEP 这类控制报文，透视时重点展示消息类型和关键字段，比如 BGP Update 里的前缀、下一跳、RT。

**报文透视示意：过一跳路由器，IP 地址不变，MAC 和 TTL 被改写**（数值为示意）

| 层 | 进入 R1 之前（PC → R1 链路） | 离开 R1 之后（R1 → R2 链路） |
|---|---|---|
| 以太 | 目的 MAC：R1 入接口的 MAC；源 MAC：PC 的 MAC；类型 0x0800 | **目的 MAC：R2 入接口的 MAC；源 MAC：R1 出接口的 MAC**（改写） |
| IP | 源 10.0.1.10 → 目的 10.0.13.2；TTL 64；协议 6（TCP） | 地址不变；**TTL 63，校验和重新计算**（改写） |
| TCP | 源端口 50000，目的端口 443 | 不变（路由器不改 TCP 头） |
| 数据 | 应用数据（例如网页内容） | 不变 |

报文透视面板就是把上面这张图做成可交互的：每一步显示报文当前的层和关键字段，这一步改了的字段高亮并显示「旧值 → 新值」。封装时新层从外面套上，解封装时从外面剥掉。到了 MPLS、SRv6、EVPN 课程，同一个面板会多出标签栈、外层 IPv6 头、SRH 等层。

### 5.4 表项面板

每台设备有自己的表：RIB、FIB、MAC、ARP、LFIB、会话表、BGP 路由表、LSDB 等。步骤里可以描述「新增、命中、修改、删除」一行，命中的行高亮。点一台设备就看它的表。

### 5.5 模拟命令行

保留两阶段提交。每课提供「本课相关命令」，display 输出从场景的同一份状态生成，和图、表保持一致。命令范围只覆盖课程用到的部分。

### 5.6 小测验

每课 3～5 题。除了选择题，还有「预测下一步」：演示停在某一步，问报文下一跳去哪、哪个字段会变成什么。

### 5.7 知识地图、进度与术语表

- 首页就是第三节的学习路径图，每个模块显示完成进度。
- 术语表：中英对照、一句话解释、出现在哪些课。讲解里的术语可以点击查看。

### 5.8 通用要求

中英双语、所有风格都能正常显示、手机可用、可以只用键盘操作、尊重系统的「减少动画」设置。

## 六、范围、非目标与内容原则

### 6.1 范围

- **网络范围**：运营商 IP 网络，包括骨干网、城域网和 IP 承载网。
- **主角设备**：路由器，原型参考华为 NetEngine 8000 系列（以 X8 为典型）。不同位置的路由器按角色区分（CE、PE、P、ASBR、RR），不为每个角色单独画一种设备。
- **深度**：原理级。讲清楚报文怎么封装、怎么走，表项怎么生成和变化，配置怎么生效。够用就好，不做设备仿真。

### 6.2 非目标

- 园区网和企业网：STP、堆叠、VLANIF 网关、VRRP 网关冗余、WLAN、防火墙上网策略等。
- 宽带接入（PPPoE、BRAS）、光传输（OTN、WDM）、移动核心网。
- 真机级仿真：命令行只覆盖课程用到的命令，界面标注「教学模拟」。
- 认证考试题库。
- 后端服务和账号系统：保持纯静态页面，学习进度只存在浏览器本地。

### 6.3 已做的交换机、防火墙、抗 DDoS 怎么处理（2026-11-07 已定）

这三类设备是在确定范围之前做的。决定如下：

- **交换机（CloudEngine S12700E）和防火墙（USG12000）保留为参考设备，不再扩展**。它们属于园区和企业网场景，学习路径不推荐它们。
- **抗 DDoS（AntiDDoS12000）移除**。K 领域（网络安全）以后讲 DDoS 流量清洗时，按运营商网络的场景重新设计。

### 6.4 内容原则

- **来源**：只用公开资料。优先华为公开的产品页、Datasheet、华为百科（info.support.huawei.com）、在线配置指南，协议细节对照 RFC。只做浏览访问，不绕过任何网站限制，打不开就如实说明。
- **准确**：参数、型号、字段都要能对应到来源；查不到的标「示意」或「待确认」。通用原理和某款设备的具体实现分开写。
- **客观**：只写客观知识，不写带主观假设的话。
- **好懂**：口语化，可以用比喻，但术语和数字要准确，中英文名称对照。
- **可追溯**：每个讲解条目登记来源链接；页面声明这是个人学习项目，不是华为官方内容。

## 八、开发流程与支持文档

这一节既是本项目的工作方式，也是一份学习软件开发流程的材料：每一步都对应业界常见的做法和文档。

### 8.1 角色

| 角色 | 谁 | 职责 |
| --- | --- | --- |
| 产品负责人（Product Owner） | 你 | 定方向和优先级，评审规格，验收成果，也是第一个学习者 |
| 开发者（Developer） | Claude | 调研，写规格和设计，实现，测试，维护文档 |
| 评审人（Reviewer） | 你 | 评审 PR，决定是否合并 |

### 8.2 流程（每个功能或课程都走一遍）

1. **需求**：想法先记进待办（backlog.md），写成用户故事 + 验收标准，不直接改代码。
2. **规格**：开工前写规格说明（docs/specs/）：目标、范围、界面草图、数据结构、验收标准、测试点。你评审通过才算可以开工。
3. **设计决策**：影响全局的技术选择写成架构决策记录（ADR），说明背景、方案对比和后果。
4. **实现**：在功能分支上小步提交，提交信息写清改了什么、为什么。
5. **测试**：Playwright 自动测试（所有风格、中英文、电脑和手机宽度、控制台无报错），再按规格里的验收标准手动走查。
6. **评审与合并**：开 PR，描述里写对应的规格编号和测试结果；你评审后合并到 main。
7. **发布**：更新在线预览，在 CHANGELOG 记一条。
8. **复盘**：每个里程碑结束做一次复盘（做得好的、要改进的、下一步），改进项进待办。

中途有新想法：先进待办，按优先级排队。当前里程碑不临时插入新功能，除非是 bug 或你明确要求。

### 8.3 就绪与完成的定义

- **就绪（Definition of Ready）**：有规格；验收标准可以检验；内容来源已找到；你已确认。
- **完成（Definition of Done）**：代码已合并；自动测试通过；所有风格和中英文可用；手机宽度可用；来源已登记；文档和 CHANGELOG 已更新；你验收通过。

| 产品规划书（本文） | docs/product-plan.md（在线版：Claude 文档） | 产品需求文档 PRD、产品路线图 | 为什么做、做什么、做到什么程度 |
| 项目规则 | CLAUDE.md | 团队约定 | 每个工作线程开工前必读的规则 |
| 文档索引 | docs/README.md | — | 所有文档的入口，说明每份文档干什么用 |
| 开发流程 | docs/process.md | 软件开发生命周期（SDLC） | 8.2 的详细版 |
| 架构设计 | docs/architecture.md | 架构文档 | 代码怎么组织，课程数据和报文模型长什么样 |
| 架构决策记录 | docs/adr/ | ADR | 每个重要技术选择为什么这么定 |
| 内容规范 | docs/content-guide.md | 风格指南 | 怎么写讲解、怎么标来源、术语怎么对照 |
| 功能规格 | docs/specs/ | 规格说明、设计文档 | 每个功能开工前的设计和验收标准 |
| 测试计划 | docs/test-plan.md | 测试计划 | 测什么、怎么测，自动和手动各管什么 |
| 待办 | docs/backlog.md | 产品待办列表（Product Backlog） | 所有想法和需求排队的地方 |
| 变更日志 | CHANGELOG.md | 发布说明 | 每个版本改了什么 |

每份仓库文档开头都有一小段「这份文档是什么、什么时候用」，读文档的同时也能学流程。
