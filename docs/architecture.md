# 架构设计

> **这份文档是什么**：代码现在怎么组织，以及 M1 之后要改成什么样。
> **什么时候用**：改代码之前先看「现状」，设计新功能时看「目标架构」。结构有变化时同步更新这里。

## 1. 约束

- 纯静态页面，无构建、无依赖：`index.html` + `css/style.css` + `js/app.js`，浏览器直接打开（见 [ADR 0001](adr/0001-static-no-build.md)）。
- 在线预览是把 CSS 和 JS 内联进 HTML 的单文件，发布为 claude.ai Artifact。
- 8 种视觉风格、中英文、电脑和手机宽度都要可用。

## 2. 现状（v0.4）

### 2.1 文件

| 文件 | 内容 |
|---|---|
| `index.html` | 页面骨架：顶栏（品牌、设备切换、风格、语言、进度）、舞台 `#stage`（SVG）、面包屑 `#crumbs`、演示切换 `#demos`、流程按钮 `#flows`、字幕 `#caption`、右侧面板（讲解 / 命令行） |
| `css/style.css` | CSS 变量（颜色、材质）、布局、各部件样式；末尾每种风格一个 `:root[data-skin="…"]` 区块 |
| `js/app.js` | 全部逻辑，约 1100 行，按区块组织（见下） |

### 2.2 `js/app.js` 区块

| 区块 | 主要内容 |
|---|---|
| 语言 | `LANG`、`L(zh,en)` 短文案 |
| 等轴测投影 | `P(x,y,z)` 把三维坐标投到屏幕；`box`、`fRect`、`tText` 等 2.5D 绘图工具 |
| 设备模型 | 路由器槽位 `SLOTS`、子卡 `PICS`、接口表 `IF`；多设备档案 `DEVS`、当前设备 `DEV` |
| 知识库 | `KB`（中文讲解条目）、`KB_EN`（英文）、`SRC`/`SRC_EN`（来源）、`kbOf(key)` 合并取用 |
| 视图 | `view` 当前视图：`chassis` / `board` / `sub` / `port` / `topo`；`render(v)` 重绘，`go(v)` 切换并显示讲解；`RT` 渲染令牌防止旧动画回调 |
| 原理演示 | `DEMOS[设备]` 登记演示 `{id, zh, en, kb, draw, flows}`；平面拓扑工具 `tNode`、`tLink`、`tTable`、`tPkt`、`later` |
| 引线标注 | `CALLOUTS`，部分风格显示编号引线 |
| 缩放平移 | `vt` 变换、`fitView`、指针事件；点击用 `elementFromPoint` 判定 |
| 讲解面板 | `showInfo(key)` 渲染一句话说明、要点、配置示例 |
| 报文动画 | 流程 `flows` → 步骤 `steps`；`playFlow`、`runStep`、`next`、`jump`；报文块 `mkTok` |
| 命令行 | `exec(line)` 解析命令；候选配置 `CIF` 与运行配置 `IF` 两阶段，`commit` 生效 |
| 风格与进度 | `SKINS`、`setSkin`、`markSeen` 已探索进度 |

### 2.3 现在的动画数据

一个流程（flow）：

```js
{ name, color, tok, foot,           // 名称、颜色、默认报文标签、结束语
  steps: [{ t,                       // 这一步的说明文字
            hl: ['id', ...],         // 高亮的部件
            paths: [[[x,y],...]],    // 报文沿这些折线移动
            pulse: [x,y],            // 或者：在某点脉冲（表示处理）
            tok, dur }] }            // 这一步的报文标签、时长
```

随步骤出现的元素用 `later(el, 流程, 步骤[, 截止步骤])` 标记，表格行用 `hide:'流程:步骤'` 标记。

### 2.4 现状的问题

1. **报文只是一个带文字的圆点**，看不到结构和字段（产品规划书「问题一」）。
2. **步骤自动跳转**（`setTimeout(next, 1500)`），学习者来不及读（「问题二」）。
3. **内容和绘图写在一起**：每个演示的拓扑、表格、步骤都写在各自的 `topoXxx()` 函数里，坐标和文字混在代码中，新增课程成本高，也很难检查内容是否准确。
4. 单文件 1100 行，继续堆课程会难以维护。

## 3. 目标架构（M1）

> 下面是方向性设计，具体以 [specs/001](specs/001-step-player-and-packet-inspector.md) 确认后的版本为准。

### 3.1 思路：引擎和内容分开

```
课程数据（纯数据，可审阅）      引擎（通用代码）
  场景：设备、链路、坐标   ──▶   拓扑绘制
  步骤：说明、动作          ──▶   分步播放器（手动为主）
  报文：分层、字段、改动    ──▶   报文透视面板 + 舞台报文块
  表项：每一步的表          ──▶   表项面板
  命令：配置示例            ──▶   模拟命令行
```

新增一课只写数据，不写绘图代码。数据里的每个事实都可以对照来源检查。

### 3.2 报文模型

报文是分层的数据（见 [ADR 0002](adr/0002-layered-packet-model.md)）：

```js
pkt: [
  { layer: 'eth',  fields: { dmac: 'R1-GE0/1/0', smac: 'PC', type: '0x0800' } },
  { layer: 'ipv4', fields: { src: '10.0.1.10', dst: '10.0.13.2', ttl: 64, proto: 6 } },
  { layer: 'tcp',  fields: { sport: 50000, dport: 443 } },
  { layer: 'data', fields: { note: '应用数据' } }
]
```

每一步可以对报文做操作，引擎负责算出新报文并标出改动：

```js
ops: [
  { set: ['eth.dmac', 'R2-GE0/1/0'] },     // 改字段
  { set: ['ipv4.ttl', 63] },
  { push: { layer: 'mpls', fields: { label: 1024, exp: 0, s: 1, ttl: 255 } } },  // 封装一层
  { pop: 'mpls' }                          // 解封装一层
]
```

- 层的定义（名称、颜色变量、字段列表、字段中英文名、说明）放在协议字典 `LAYERS` 里，所有课程共用。
- 层颜色用 CSS 变量（`--l-eth`、`--l-ip` 等），每种风格可以重定义。

### 3.3 分步播放器

- 状态：`{ lesson, flow, step, auto: false }`。
- 每一步的状态（报文、表项、显示的元素）由「初始状态 + 前 N 步的操作」计算出来，所以可以任意跳到第 N 步，也可以后退（见 [ADR 0003](adr/0003-manual-step-player.md)）。
- 默认手动：动画播完停住，等学习者点「下一步」。

### 3.4 文件拆分（M1 时决定）

在保持「无构建」的前提下，可以把 `app.js` 拆成多个 `<script>` 文件（引擎、协议字典、各课程数据），Artifact 打包时按顺序内联。是否拆、怎么拆，在 spec 001 里定。
