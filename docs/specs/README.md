# 功能规格说明（Specs）

> **这份文档是什么**：每个功能或课程开工前的设计说明，写清楚做成什么样、怎么验收。
> **什么时候用**：从 backlog 挑一条开工之前写；评审通过（状态「已确认」）后才能写代码。

## 为什么先写 spec

写代码之前把「做成什么样」想清楚、写下来，让产品负责人在改动还便宜的时候就能提意见。到了代码评审阶段再发现方向不对，成本要高得多。

## 规则

- 一个 spec 一个文件：`NNN-短标题.md`，按 [template.md](template.md) 写。
- 状态：`草稿` → `评审中` → `已确认` → `已实现`。
- 实现过程中发现 spec 要改，先改 spec 并说明，再改代码。
