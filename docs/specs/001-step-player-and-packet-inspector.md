# 001 · 分步播放器与报文透视

- 状态：草稿（M0 合并后进入评审）
- 里程碑：M1
- 对应 backlog：B-101、B-102、B-103（B-104～B-107 另写 spec）
- 日期：2026-11-06

## 1. 目标

解决产品规划书里提出的两个问题：

1. **报文看不清**：现在报文是一个彩色圆点加文字，学习者看不到它的结构、每层带什么关键信息、经过设备时哪些字段变了。
2. **步骤跳太快**：每一步播完 1.5 秒自动进入下一步，读不完说明。

## 2. 范围与非目标

- 做：
  - 分步播放器：默认手动，支持上一步 / 下一步 / 重播 / 步骤列表 / 可选自动播放 / 键盘。
  - 报文透视面板：分层显示报文结构和关键字段，改动高亮。
  - 舞台报文块：从圆点改成分层色条，颜色和透视面板一致。
  - 协议字典 `LAYERS` 的第一批层：以太、802.1Q、IPv4、IPv6、TCP、UDP、ICMP、MPLS、数据。
  - 用新播放器重做路由器的「IP 寻址与路由表」演示，作为样板。
- 不做（另写 spec）：
  - 表项面板、新页面布局、全部演示迁移、课程数据格式的完整定义。
  - 字节视图。

## 3. 界面

```
┌──────────────── 舞台 ────────────────┐┌── 右侧面板 ──────────┐
│                                       ││ [讲解][报文][命令行] │
│   PC ──▶ [▮▮▮▮] ──▶ R1 ──▶ R2         ││                      │
│          分层色条报文块                ││ 报文（第 3 步）      │
│                                       ││ ▌以太                │
│                                       ││   目的 MAC  R1 → R2  │← 高亮
│                                       ││   源 MAC    PC → R1  │← 高亮
├───────────────────────────────────────┤│ ▌IPv4                │
│ ‹ 上一步  3 / 6  下一步 ›  ↻  ☰  ▶自动 ││   TTL       64 → 63  │← 高亮
│ R1 查路由表，命中 10.0.13.0/24……      ││ ▌TCP …               │
└───────────────────────────────────────┘└──────────────────────┘
```

- 步骤条放在舞台下方，显示步骤号、说明文字和控制按钮。
- 报文透视在右侧面板的「报文」标签页。手机上右侧面板在舞台下方。
- 舞台上的报文块是一个横向分层色条（每层一段，外层在左），旁边一个短标签；点击报文块切到「报文」标签页。

## 4. 数据结构

### 4.1 协议字典

```js
const LAYERS = {
  eth:  { zh:'以太', en:'Ethernet', color:'--l-eth',
          fields:{ dmac:{zh:'目的 MAC',en:'Destination MAC'}, smac:{zh:'源 MAC',en:'Source MAC'},
                   type:{zh:'类型',en:'EtherType'} }, src:'…' },
  ipv4: { zh:'IPv4', en:'IPv4', color:'--l-ip',
          fields:{ src:{…}, dst:{…}, ttl:{…}, proto:{…}, dscp:{…} }, src:'RFC 791' },
  // dot1q, ipv6, tcp, udp, icmp, mpls, data …
};
```

### 4.2 步骤

```js
{ t: L('R1 查路由表……','R1 looks up…'),   // 说明
  hl: ['r1'],                                 // 高亮
  paths: [...], pulse: [...],                 // 动画（沿用现有）
  pkt: [...],                                 // 可选：直接给出整个报文（一般只在第 1 步）
  ops: [{ set:['ipv4.ttl',63] }, { set:['eth.dmac','R2'] }],  // 可选：报文操作
  show: ['row-rt3'], hide: [] }               // 可选：舞台元素显隐（替代 later/data-hide）
```

第 N 步的报文 = 第 1 步的 `pkt` 依次执行第 2～N 步的 `ops`。

## 5. 交互细节

- 点流程按钮：进入第 1 步，播完动画后停住。
- 下一步：按钮、键盘 →、空格。上一步：按钮、键盘 ←。到第 1 步时上一步不可用，最后一步时下一步变成「重播」。
- 重播 ↻：重新播放本步动画，不改变状态。
- 步骤列表 ☰：列出所有步骤的说明，点哪步跳哪步。
- 自动播放：默认关；打开后每步停留时间 = max(3 秒, 说明字数 × 0.25 秒)，可随时暂停。开关状态记在 localStorage。
- 动画进行中点下一步：直接跳到本步结束状态，再进入下一步。
- `prefers-reduced-motion`：不做移动动画，报文块直接出现在终点。

## 6. 内容与来源

- 以太帧字段：IEEE 802.3（公开摘要）、华为百科「以太网」相关词条。
- IPv4 头：RFC 791；DSCP：RFC 2474。
- TCP 头：RFC 9293。
- MPLS 标签：RFC 3032。
- 示例地址、MAC、端口标「示意」。

## 7. 验收标准

- [ ] 任何演示中，一步的动画播完后都停住，不点下一步不会继续。
- [ ] 上一步、下一步、步骤列表跳转后，舞台元素、报文透视、高亮都和「从第 1 步顺序播放到该步」一致。
- [ ] 路由演示中，每一步的报文透视显示 以太 / IPv4 / TCP / 数据 四层和关键字段；经过 R1 后，目的 MAC、源 MAC、TTL 高亮并显示旧值 → 新值。
- [ ] 舞台报文块是分层色条，层的颜色和透视面板左侧色条一致。
- [ ] 8 种风格、中英文、1400 和 390 宽度下都可用，无横向滚动，`node tests/smoke.js` 通过。
- [ ] 键盘 ←/→/空格可用；自动播放可开关。
